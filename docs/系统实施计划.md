# 班级 AI 趣味编程平台实施计划

## 1. 项目目标

建设一个仅供校园局域网使用的班级趣味编程平台。学生登录后，可以在平台内与 AI 编程助手对话，生成或修改单文件 HTML/CSS/JavaScript 小游戏和小应用，在安全沙箱中预览，完成后发布到本班作品广场。教师负责班级、学生、AI 额度和作品管理，并可将优秀作品加入跨班精选。

第一版采用独立项目，不修改现有 `ai-workshop-web`。

## 2. 技术架构

- 项目目录：`class-code-lab`
- 前端：React、Vite、CodeMirror 6
- 后端：Go、Gin、GORM
- 数据库：默认 SQLite 便携部署；也支持 MySQL 独立数据库
- AI 接口：OpenAI Chat Completions 兼容协议
- 主平台端口：`8080`
- 代码 Runner 端口：`8081`
- 使用规模：约 100 名学生，目标支持 60 人同时在线

选择标准的 `POST /v1/chat/completions` 兼容协议，以适配更多模型供应商。后续如果固定使用官方 OpenAI，可以在模型网关内部增加 Responses API 适配器，不影响前端和业务接口。

## 3. 账号、班级与权限

- 教师创建班级，通过 Excel 导入学生，导入字段为班级、姓名、可选登录名。
- 学生登录时选择班级和姓名，使用统一初始密码 `123456`。
- 后端强制首次修改密码；未完成改密时只能访问退出和修改密码接口。
- 每个班级具有登录开关，教师可在上课前开放、课后关闭。
- 教师可重置密码、锁定账号、查看最后登录时间和首次改密状态。
- 学生接口不接受前端传入的班级身份，所有班级条件均从登录会话获得。
- 学生默认只能读取本班作品；跨班精选是唯一允许的跨班只读入口。
- 登录使用数据库会话和 `HttpOnly` Cookie，不将认证令牌存入 localStorage。

统一初始密码仍存在别人抢先登录的风险，因此必须同时提供班级登录开关、登录限速、首次强制改密和教师快速重置功能。

## 4. 学生创作流程

1. 登录并完成首次改密。
2. 进入创作工作台，通过创意引导卡描述作品类型、主题、玩法和风格。
3. 与 AI 编程助手对话，生成第一版完整 HTML。
4. AI 返回文字说明和代码提案，但不会直接修改作品。
5. 学生点击“应用到编辑器”，系统保存旧版本后更新草稿。
6. 学生在 Runner 沙箱中预览，查看运行错误并可让 AI 协助修复。
7. 学生填写作品名称和简介，一键发布到本班作品广场。
8. 修改草稿不会影响已发布版本，再次发布时才更新发布快照。
9. 教师为班级设置每名学生的评分积分，学生把积分分配给本班其他同学作品，系统实时生成排行榜和冠亚季军。

第一版每名学生仅有一个作品，但允许保存多次历史版本、撤销和重新发布。

## 5. AI 模型网关

### 5.1 数据库配置

- AI 服务及全局默认设置由教师在后台维护，保存在数据库。每组服务可设置地址、API Key、模型、并发、超时、输出上限、思考强度和启用状态。
- 首次升级时可将旧 `AI_*` 环境变量导入一次；之后只使用数据库配置。
- API Key 不通过读取接口返回，但直接存储在数据库中。数据库及备份均需作为敏感数据保管。
- 未配置可用服务时，AI 接口返回“模型服务未配置”，其他功能继续可用。

### 5.2 请求与响应

- 后端请求所选服务的 `{BaseURL}/chat/completions`。
- 使用 `Authorization: Bearer <API_KEY>`。
- 支持上游 SSE 流式回答；前端统一接收 `delta`、`done` 和 `error` 事件。
- 供应商忽略流式参数时，兼容普通 JSON 响应。
- 每组服务分别限制并发。按运行中请求数与容量比例选择，满载时等待；输出开始前遇到可切换故障时换用另一服务。
- 临时故障冷却 60 秒；鉴权失败需更新配置或连接测试成功才能恢复。
- 每名学生同一时间只能有一个请求，每班并发默认不超过六个，其余进入队列。
- 保存服务名、模型名、耗时、结果状态以及供应商返回的输入/输出 Token；用量缺失时允许为空。
- DeepSeek 使用 `max_tokens` 控制输出；思考强度支持固定值和自动模式，自动模式按任务复杂度在 `none`、`low`、`high` 之间选择，连接测试仍使用 `none`；其他 OpenAI 兼容供应商保持 `max_completion_tokens`。
- 记录 DeepSeek 返回的缓存命中/未命中 Token，教师端显示缓存命中率。
- 模型历史默认最多携带 8 条、16000 字符，且不重复携带历史 AI 回复中的完整 HTML 代码块。
- 首次生成使用完整 HTML；已有作品优先使用唯一精确匹配的 JSON 增量补丁，服务端重建完整代码后再执行安全检查。
- 新对话、首次生成、后续修改和全量重试均使用 393216 Token 最大输出上限；选择自动模式时，新作品和普通修改使用 `low`，简单样式修改使用 `none`，复杂修改和全量重试使用 `high`，模型正常完成时会提前停止。
- 解析并保存 `finish_reason`；如果为 `length`，本次请求标记失败，不创建代码提案。

### 5.3 AI 教学规则

系统提示将模型限定为面向中学生的中文编程助教：

- 表达简短、友好，避免堆砌术语。
- 想法不清楚时最多提出两个简单问题。
- 生成完整的单文件 HTML，而不是零散代码片段。
- 修改作品时返回完整新版本，并说明本次修改内容。
- 不生成支付、账号收集、密码输入、文件上传或个人信息采集功能。
- 不生成页面跳转、弹窗、下载、摄像头、麦克风或任意网络请求。
- 只使用平台允许的固定版本 CDN。
- 游戏应提供明确玩法、开始方式和重新开始方式。

模型回答中最大的一个 `html` 代码块会被识别为代码提案。没有 HTML 代码块时，回答只作为讲解，不修改作品。

## 6. 代码运行安全

- 学生代码通过有效期约五分钟的运行令牌，在 `8081` Runner 中加载。
- iframe 仅设置 `sandbox="allow-scripts"`，不开放同源、表单、弹窗、下载和顶层跳转权限。
- Runner 使用 CSP 禁止 fetch、XHR、WebSocket、Worker、WebAssembly、`eval`、嵌套网页和任意非白名单资源。
- 仅允许带明确版本号的 `cdn.jsdelivr.net` 和 `cdnjs.cloudflare.com`。
- HTML 解析检查危险标签、`javascript:` 地址、非法外链和明显死循环。
- AI 生成代码、学生粘贴代码和已发布代码执行完全相同的安全检查。
- 作品列表页不运行代码，只有进入作品详情后才加载单个作品。
- 提供停止、重新加载和错误报告功能；浏览器仍无法绝对防止所有死循环，因此教师必须能够立即撤下或锁定作品。

## 7. 教师管理能力

- 创建、停用和切换班级。
- 导入名单、查看登录和改密状态、重置密码、锁定账号。
- 开启或暂停班级 AI，设置每名学生请求次数和班级并发量。
- 查看模型健康状态、排队情况、请求数、Token 用量、失败率和学生对话记录。
- 查看所有草稿/发布状态，安全预览学生作品。
- 撤下、锁定作品，以及加入或移出跨班精选。
- 查看登录、改密、发布、撤下、密码重置和精选等审计日志。

## 8. 核心数据

- `classes`：班级和登录状态。
- `users`：教师、学生、班级、登录名、密码哈希、改密和锁定状态。
- `teacher_class_access`：教师可管理班级。
- `sessions`：登录会话。
- `works`：当前草稿、发布快照、发布状态和精选状态。
- `work_revisions`：手动修改和 AI 修改的历史版本。
- `ai_conversations`、`ai_messages`、`ai_code_proposals`：AI 对话和代码提案。
- `ai_usage_logs`、`class_ai_settings`：模型用量和班级额度。
- `audit_logs`：关键操作审计。

学生 AI 对话会保存并允许教师查看，学生界面必须明确提示。发送给模型的内容不得包含学生真实姓名、班级名单、密码或其他身份信息。

## 9. 主要接口

- `POST /api/auth/login|logout|change-password`
- `GET|PUT /api/student/work`
- `POST /api/student/work/preview-token|publish`
- `POST /api/student/ai/messages`
- `GET /api/student/ai/history`
- `POST /api/student/ai/proposals/:id/apply`
- `GET /api/gallery|featured`
- `POST /api/gallery/:id/run-token`
- `POST /api/teacher/classes/:id/import`
- `POST /api/teacher/students/:id/reset-password`
- `PUT /api/teacher/classes/:id/ai-settings`
- `GET /api/teacher/ai/usage|conversations|health`
- `POST /api/teacher/works/:id/unpublish|lock|feature`
- `GET /run/:token`

## 10. 构建与本轮验收范围

完成代码后只进行基础工程验证：

- 后端执行 `go test ./...` 和 `go build ./...`。
- 前端执行 `npm ci` 和 `npm run build`。
- 使用模拟 OpenAI 兼容服务器测试请求参数、Bearer 鉴权、流式解析、普通响应、401、429 和超时。
- 测试首次改密、班级隔离、AI 次数限制、代码提案应用、版本恢复和发布快照。
- 测试 Runner 的无效令牌、过期令牌、CSP 和危险代码拒绝。
- 启动 MySQL、主服务和 Runner，确认健康检查接口正常。
- 未提供真实模型密钥时不发起付费请求，只验证“AI 未配置”降级路径。

本轮不负责校园服务器部署、域名、HTTPS、真实模型费用测试和完整浏览器业务验收。学生端和教师端的具体页面操作由用户后续验证。
