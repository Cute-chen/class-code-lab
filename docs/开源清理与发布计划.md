本计划只描述开源前需要完成的工作。每项工作完成后，应在本文件中勾选，并保留验证结果或链接。

```bash

git grep -n '10\.132\.' $(git rev-list --branches --tags)  # 使用历史扫描工具替代也可以
```

## 5. 密钥、默认配置和运行数据

### 5.1 密钥扫描

扫描当前文件、未跟踪文件、构建产物和 Git 历史中的：

- API Key、Bearer Token、Cookie、私钥、证书。
- 数据库密码、模型服务地址、内网域名。
- 导出的 JSON、CSV、Excel、SQLite 数据库和日志。

建议检查：

```bash
git status --short --untracked-files=all
rg -n -i 'api[_-]?key|secret|token|password|bearer|private key|BEGIN .*PRIVATE' .
git log --all --stat
```

如发现历史密钥：

- 立即撤销或轮换密钥。
- 使用 `git filter-repo` 或等效工具清理历史。
- 清理后重新扫描，确认没有仅靠当前文件删除而留下的历史副本。

### 5.2 默认管理员配置

本项目面向受控局域网，保留默认管理员账号 `teacher / 123456`，首次登录后强制改密。公开文档需要明确这一使用条件。

- 不把真实 `.env`、数据库和运行日志放入仓库。

## 6. 安全与部署前检查

### 6.1 代码 Runner

复核以下安全边界，并把限制写入文档：

- 沙箱 iframe、CSP、权限策略和短期运行令牌。
- 学生代码静态检查的覆盖范围和已知绕过可能性。
- 外部 CDN 白名单、版本号要求和浏览器联网依赖。
- Runner 与主服务分端口时的防火墙和反向代理配置。

必须明确：静态检查和浏览器沙箱不是数学意义上的安全保证，公网部署前需要额外隔离和安全评估。

### 6.2 认证和隐私接口

- 审查公开班级名单接口是否适合公网使用；当前会返回学生姓名和登录名。
- 检查登录限流、会话 Cookie、CSRF、CORS、错误信息和日志内容。
- 确认 API Key 不会通过读取接口、前端日志或错误响应返回。
- 检查教师权限、跨班作品访问和 Runner 令牌授权。

### 6.3 部署边界

README 需要明确项目当前面向校园局域网，不等于已完成公网生产加固。补充：

- HTTPS、反向代理和安全 Cookie 的配置方式。
- SQLite 与 MySQL 的适用范围。
- 备份数据库时保护 AI API Key 和学生数据。
- 多实例部署目前不共享 AI 调度状态的限制。
- 尚未完成真实 60 人并发压测的事实。

## 8. Git 仓库整理

按以下顺序操作：

1. 记录当前工作区状态，确认未提交修改的归属。
2. 删除或忽略构建产物、数据库、日志、系统文件和本机配置。
3. 完成敏感内容、真实姓名、内网地址和品牌素材替换。
4. 检查 Git 历史；如有敏感内容，先轮换密钥，再重写历史。
5. 重新运行全文扫描和依赖扫描。
6. 创建开源前整理提交，提交信息清楚说明清理范围。
7. 再添加 GitHub/GitLab 等远端，确认默认分支和仓库可见性后推送。

推送前禁止出现：

- `.env`、数据库、真实课堂导出文件、日志、私钥和 API Key。
- 未授权校徽、学生姓名、学号或真实作品。
- 学校内部 IP、域名、服务器名和机房网络拓扑。
- 本机绝对路径和开发者个人配置。
