# 班级 AI 趣味编程平台——教师端与学生端具体设计

## 1. 设计目标

平台主要在学校电脑、教室投影和普通笔记本上使用，优先适配 1366×768 及以上桌面屏幕。核心设计原则如下：

1. 学生端先帮助完成作品，再逐步暴露代码细节，避免一进入系统就面对复杂开发工具。
2. 教师端突出课堂状态、异常和可立即执行的管理动作，不堆叠无关统计。
3. 所有保存、生成、排队、发布和失败操作必须有明确反馈。
4. AI 只提出修改方案，学生始终保留是否应用和是否发布的决定权。
5. 普通错误要提供下一步操作，例如“重新请求”“恢复上一版”“联系教师”，不能只显示错误代码。

## 2. 视觉系统

### 2.1 整体风格

- 浅色优先，适合白天机房和投影环境。
- 学生端使用适度活泼的蓝紫色和圆角卡片，体现创作感，但不使用幼儿化装饰。
- 教师端使用相同设计语言，但减少装饰和大面积渐变，保持信息密度与专业感。
- 代码编辑器保持深色主题，与普通内容区形成清晰分区。
- 不使用 Emoji 作为导航和功能图标，统一使用 Lucide SVG 图标。

### 2.2 色彩变量

| 用途 | 颜色 |
| --- | --- |
| 主色/主要按钮 | `#2563EB` |
| AI/创意强调色 | `#7C3AED` |
| 成功/已发布 | `#16A34A` |
| 等待/额度提醒 | `#D97706` |
| 错误/撤下/锁定 | `#DC2626` |
| 页面背景 | `#F6F8FC` |
| 卡片背景 | `#FFFFFF` |
| 主要文字 | `#172033` |
| 次要文字 | `#64748B` |
| 边框 | `#DCE3EE` |
| 代码编辑器背景 | `#0F172A` |

### 2.3 字体与交互

- 中文字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 正文默认 15～16px，表格和辅助信息不低于 13px。
- 所有主要按钮高度至少 40px，学生端关键按钮建议 44px。
- 键盘焦点必须可见；错误信息使用 `role="alert"`。
- 超过 300ms 的请求显示加载状态，并禁用重复提交。
- 动画控制在 150～250ms，同时支持 `prefers-reduced-motion`。

## 3. 全局信息架构

### 3.1 学生端导航

学生登录后默认直接进入创作工作台，顶部提供：

- 我的创作
- 本班广场
- 跨班精选
- 当前班级、AI 剩余次数、保存状态、学生姓名和退出

首次未改密时不显示正常导航，只进入强制改密页。

### 3.2 教师端导航

教师端使用左侧固定导航和顶部班级切换器：

- 课堂总览
- 学生管理
- 作品管理
- AI 对话与用量
- 班级设置
- 操作记录

教师切换班级后，所有页面筛选保持一致；跨班精选和系统健康状态属于全局视图。

## 4. 学生端页面设计

### 4.1 登录页

页面只保留必要步骤：

1. 选择班级。
2. 选择自己的姓名。
3. 输入密码。
4. 点击“进入创作空间”。

交互要求：

- 班级未开放登录时显示“教师暂未开放本班登录”，不显示密码错误。
- 姓名列表支持搜索，避免班级人数较多时滚动困难。
- 连续失败后显示等待时间，不暴露账号是否被锁定的内部细节。
- 登录页不展示作品和班级名单以外的信息。

### 4.2 首次改密页

- 显示“为了防止别人进入你的作品，请先设置新密码”。
- 输入旧密码、新密码和确认密码。
- 实时显示最少六位、不能使用 `123456`、两次密码一致等检查结果。
- 成功后清除当前会话并返回登录页，要求使用新密码重新登录。

### 4.3 创作工作台

桌面端采用左右分栏：左侧约 36% 为 AI 助手，右侧约 64% 为作品区。

```text
┌──────────────────────────────────────────────────────────────┐
│ Logo  我的创作  本班广场  跨班精选   AI剩余  保存状态  用户 │
├───────────────────────┬──────────────────────────────────────┤
│                       │  [代码] [预览]      保存  发布        │
│ AI 编程助手           │                                      │
│                       │  CodeMirror 或 Runner                 │
│ 对话记录/创意引导     │                                      │
│                       │                                      │
│ 代码提案卡片          │                                      │
│                       ├──────────────────────────────────────┤
│ 输入框        发送    │  运行状态 / 错误提示 / 恢复上一版     │
└───────────────────────┴──────────────────────────────────────┘
```

#### 空作品状态

AI 区先显示创意引导卡：

- 想做什么：点击、躲避、接物、问答、模拟器、其他。
- 主题是什么。
- 玩家怎样操作。
- 希望采用什么视觉风格。

完成后生成一条可编辑的问题，学生确认后再发送给 AI。学生也可以跳过引导直接输入。

#### AI 对话区

- 流式输出时显示“AI 正在编写”，发送按钮变为停止按钮。
- 请求排队时显示前方数量，不允许重复提交。
- 顶部固定显示本节剩余请求次数。
- 快捷操作包括：生成第一版、解释代码、修复错误、优化画面、增加计分、增加重新开始。
- AI 文字和代码提案分开显示，代码不直接铺满聊天记录。

#### 代码提案卡片

卡片展示：

- 本次修改摘要。
- 建议作品名称。
- 代码大小和安全检查状态。
- “应用到编辑器”“查看代码差异”“放弃”三个操作。

应用前如果当前草稿有未保存修改，系统先自动保存一个历史版本。安全检查失败时不允许应用，并明确说明需要让 AI 修改的原因。

#### 代码标签页

- 使用 CodeMirror，默认折叠不重要的长内容。
- 顶部提供保存、格式化和恢复上一版。
- 显示“已保存”“保存中”“保存失败”三种稳定状态。
- 不默认展示复杂的文件树、终端或开发者设置。

#### 预览标签页

- 必须由学生点击“运行预览”后才加载 Runner。
- 工具栏提供重新运行、停止、适应窗口和将错误交给 AI。
- 运行错误显示中文摘要和原始错误折叠区。
- 死循环或 Runner 无响应时提供“强制停止预览”。

#### 发布流程

点击发布后打开确认面板：

- 作品名称。
- 作品简介。
- 当前安全检查结果。
- 发布后本班同学可以体验的提示。

发布成功后提供“去作品广场看看”和“继续修改”两个入口。继续修改只影响草稿，直至再次发布。

### 4.4 本班作品广场

- 顶部显示班级名称、已发布数量和搜索框。
- 顶部显示个人评分总额度、已使用积分和剩余积分，花完后标记“已完成评分”。
- 卡片展示发布时自动截取的运行首帧封面、作品名称、作者、简介、总积分、支持人数、个人已投积分和“开始体验”；封面未生成时使用默认图标。
- 不在列表卡片中运行作品，只加载静态封面图片，也不自动播放音频。
- 默认按总积分排名，支持切换最近发布和作者姓名；总积分相同时依次比较支持人数、发布时间和作品 ID。
- 仅允许给本班其他同学已发布且未锁定的作品评分，积分可随时调整并立即计入排行榜。
- 前三名展示冠军、亚军和季军；跨班精选不参与评分，不公开具体投票人身份。
- 当前学生自己的卡片增加“我的作品”标识。

### 4.5 作品体验页

- 页面顶部显示返回广场、作品信息和作者。
- 中间为单一 Runner 区域。
- 提供重新运行、停止和全屏体验。
- 跨班精选作品明确显示来源班级。
- 作品已被撤下时显示统一不可用页面，不泄露撤下原因。

### 4.6 学生端关键异常状态

- AI 未配置：保留手动编辑、粘贴和发布功能。
- AI 暂停：提示教师暂时关闭了 AI。
- 额度用完：不隐藏历史对话，提示仍可手动修改。
- 模型繁忙：保留输入内容并允许稍后重试。
- 代码被拦截：列出可理解的具体原因和修复建议。
- 保存失败：将未保存内容保留在浏览器内存，提供重新保存按钮。
- 账号或作品锁定：停止编辑并提示联系教师。

## 5. 教师端页面设计

### 5.1 课堂总览

教师登录后的默认页，顶部先显示模型状态和班级开关。

第一行状态卡：

- 班级登录：开放/关闭。
- AI 助手：开放/暂停。
- 已登录人数/班级人数。
- 已发布作品数。
- 当前 AI 队列和失败请求数。

第二部分为学生进度表：

| 学生 | 登录/改密 | 作品状态 | AI 使用 | 最近操作 | 快捷操作 |
| --- | --- | --- | --- | --- | --- |

快捷操作只保留重置密码、增加 AI 次数、查看作品和锁定账号。状态每 10 秒轻量刷新，并提供手动刷新；第一版不要求 WebSocket。

### 5.2 学生管理

- 顶部提供导入 Excel、下载模板、添加单个学生和批量操作。
- 表格显示姓名、登录名、班级、改密状态、最后登录、账号状态和作品状态。
- 支持按未改密、未登录、被锁定和未发布筛选。
- 密码重置必须二次确认，重置后显示统一初始密码提示，不在列表长期显示密码。
- 删除已有作品或对话的学生时采用停用，不直接物理删除关联数据。

### 5.3 作品管理

- 默认按班级显示卡片或紧凑列表，可切换“全部、已发布、已撤下、已锁定、跨班精选”。
- 教师预览也通过 Runner，不在管理页面直接执行源代码。
- 详情抽屉展示作品信息、发布版本、安全检查、代码大小和学生最近修改时间。
- 主要操作：撤下、恢复展示、锁定编辑、解锁、加入精选、取消精选。
- 撤下和锁定为危险操作，要求确认并填写可选备注，记录到审计日志。

### 5.4 AI 对话与用量

页面分为三个标签：

1. 使用概况：请求量、成功率、平均耗时、Token 用量、当前队列。
2. 学生对话：按班级、学生、日期和拦截状态筛选。
3. 异常记录：鉴权失败、限流、超时、内容拦截和解析失败。

设计要求：

- Token 用量仅展示供应商实际返回的数据，缺失时显示“未提供”，不显示为零。
- 不根据固定单价自动声称真实费用；如配置了价格才显示估算，并标注“估算”。
- 对话详情明确区分学生输入、AI 文字回答和代码提案。
- 教师可以暂停单个学生的 AI 权限或增加剩余次数。

### 5.5 班级设置

- 班级名称、登录开关、AI 开关。
- 每名学生请求上限、班级并发数和请求冷却时间。
- 每名学生作品评分积分；大于 0 时自动开放评分，设为 0 时暂停修改并保留排行榜。
- 发布是否开放、是否允许学生继续修改已发布作品。
- 模型区域只显示供应商地址、模型名和连接状态，不回显 API Key。
- 提供“测试模型连接”按钮，测试结果包含耗时和错误摘要，不显示密钥或完整供应商响应。

### 5.6 操作记录

- 记录时间、操作者、班级、对象、动作和结果。
- 支持筛选登录、改密、密码重置、锁定、发布、撤下和精选。
- 不记录密码、API Key、完整 Cookie 或学生代码正文。

## 6. 响应式与课堂投影

- 主要目标宽度为 1366px 和 1440px。
- 1024px 以下学生工作台改为“AI 助手/作品区”二选一标签，不强行保留双栏。
- 教师表格在窄屏下保留姓名和状态，次要列进入详情抽屉。
- 教师课堂总览应适合投影，但投影模式默认隐藏登录名、对话正文等敏感信息。
- 375px 手机宽度只保证查看和基础操作，不将手机作为主要代码编辑设备。

## 7. UI 验收清单

- 首次使用者无需说明即可完成登录、改密、生成、预览和发布。
- 所有异步操作均有加载、成功或失败反馈。
- AI 请求期间不能重复点击发送。
- 错误信息出现在相关操作附近，并提供恢复路径。
- 键盘可以完成登录、切换标签、发送消息和发布。
- 主要文字与背景对比度不低于 4.5:1。
- 所有图标按钮具有文字标签或可访问名称。
- 作品列表不会自动运行任何学生代码。
- 教师投影模式不会展示学生密码、登录名或完整私密对话。
- 模型未配置、模型超时和额度耗尽时，学生仍能手动编辑和发布作品。
